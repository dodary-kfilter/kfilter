# 매수 후보 TOP 20 (v3, 2026-10-20~)

국장·미장 각각 두 목록을 뽑는다.
- **상승 확률 20**: 상승 확률이 높은 순서
- **기대 수익 20**: 오를 확률이 내릴 확률보다 높은(51% 이상) 종목 중 기대 수익(상승 확률 × 오르면 + 하락 확률 × 내리면)이 큰 순서 — 0 이하는 뺀다
  (2026-10-23: '오르면'만으로 줄 세우면 크게 흔들리는 종목을 고르는 복권이 되어 바꿨다)

## 후보
- 국장: 코스피 200 + 코스닥 150 — 거래소 구성 목록은 막혀 있어(data.krx.co.kr) 다음 시가총액 순위로 근사(보통주, 스팩·리츠 제외)
- 미장: S&P 500(위키백과 목록) + 나스닥 100(나스닥 API)

## 계산 (두 단계로 나눠 서로 섞이지 않게)
1. 상승 확률 P↑ = 시장 몫 + 종목 판단(Δ)
   - 시장 몫 = Σ 갈래 확률 × Φ(베타 × 갈래별 지수 움직임 ÷ 고유 흔들림) — 시장 갈래는 meta.scenarios
   - 종목 판단 Δ = ±%p(최대 15) — `judgments.json`, 판단 갱신 때 채팅에서 매긴다. 없으면 0(화면에 '판단 전')
2. 폭: 종목 판단을 넣지 않은 분포에서 오른 경우·내린 경우의 평균 — 시장 갈래와 흔들림만으로 계산

## 갱신
- 매주 토요일 08:30 자동(`.github/workflows/top20.yml` → `python3 top20/tools/build.py`): 후보 목록, 시세, 베타·흔들림, 시장 몫·폭, 두 목록을 새로 만든다. 판단(Δ)은 그대로.
- 판단 갱신(채팅): 두 목록에 든 종목과 그 문턱 근처 종목을 우선 Δ로 매기고 `judgments.json`에 적는다. 판단일은 `judgments.json`의 meta.judged와 top20.json의 meta.judged.
- 2026-10-20 전환 때 10/17 판단(고유 기대 %)은 같은 종목의 확률 가감(%p)으로 옮겨 넣었다.

# 매수 후보 TOP 20

국장·미장 매수 후보를 앞으로 3개월(한 분기) 기준으로 판단해 20개씩 정리한 자료입니다.
사이트(루트의 index.html)의 **TOP 20 탭**이 `top20.json`을 읽어 그대로 보여 줍니다(읽기만 함). 이 폴더의 도구는 사이트·스캔 파일(index.html, data.json, scanner.py 등)을 읽거나 바꾸지 않습니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `top20.json` | 최신 판단 원본. 종목별 상승·하락 확률, 오르면·내리면 평균, 고유 기대, 행동, 코멘트, 근거, 차트 자리, 실적·수급 |
| `history/YYYY-MM-DD.json` | 갱신할 때마다 그날의 판단을 통째로 보관 (3개월 뒤 채점용) |
| `tools/refresh.py` | 시장 자료(가격·변동성·베타·옵션 변동성·월봉/주봉·외국인 지분율)를 새로 받아 확률·폭·순위를 다시 계산 |
| `tools/build_page.py` | (선택) `top20.json`으로 따로 보는 페이지(HTML)를 생성. 사이트 TOP 20 탭이 같은 내용을 보여 주므로 평소엔 쓰지 않는다 |

## top20.json 구성

- `meta`: 기록일(`record_date` — 숫자 갱신일), 판단일(`judged` — 판단 항목을 마지막으로 검토한 날), 기준 가격일, 예측 기간, 문턱(국장 55%, 미장 60%), 시장 시나리오(갈래별 확률·지수 움직임), 변동성 출처, 결론 문구
- `kr`, `us`: `top`(매수 후보 20), `out`(제외 종목과 이유), `bench`(20위 밖 대기, 있을 때만)
- 종목 항목 중 사람이 판단해서 고치는 것: `alpha`(고유 기대, %), `act`(행동), `cm`(주요 코멘트), `why`(판단 근거), 실적·추정치 항목
- 미장 종목은 `kn`(한글 종목명)을 함께 둔다. 사이트 카드와 종목별 프롬프트가 쓰므로, 새 미장 종목을 넣을 때 반드시 채운다
- 갱신기가 자동으로 고치는 것: 가격, 10일선, 하루 급락 기준, 1년 종가 고점, `mw`(월봉·주봉·차트 자리), 베타·흔들림, 시나리오 결과, 외국인 지분율(국장), 순위

## 계산 방식 (요약)

- 3개월 결과 = 시장 세 갈래(좋은 장·나쁜 장·횡보) x (베타 x 지수 움직임 + 고유 기대) + 고유 흔들림
- 흔들림: 미장은 옵션 내재 변동성(만기 60~120일, 행사가 ±5%), 국장은 지난 120거래일 실현 변동성
- 순서: 상승 확률이 문턱을 넘은 종목을 오를 폭 순으로 먼저, 나머지는 상승 확률 순

## 갱신 절차

주기: 매주 토요일(금요일 종가 기준). 국장·미장을 같은 날 종가로 맞추고, 평일 수급 스캔과 커밋이 겹치지 않게 한다.

- **숫자는 자동**: `.github/workflows/top20.yml`이 매주 토요일 08:30(한국시간)에 갱신기를 돌려 가격·변동성·확률·순위를 고친다. 판단 항목과 판단일(`meta.judged`)은 그대로 둔다. 못 받은 종목이 10개를 넘으면 덮어쓰지 않는다.
- **판단은 채팅**: 고유 기대·후보 교체는 사람이 판단해야 해서 채팅에서 고친다. 판단일이 7일 넘게 묵었으면 다음 대화에서 먼저 갱신하고, 고친 날을 `meta.judged`에 적는다. 사이트 TOP 20 기준 줄에 숫자 갱신일과 판단일이 따로 보인다.

```bash
# 1) 시장 자료 갱신 (판단 항목은 그대로 유지) — 토요일엔 자동으로 이미 돌아 있다
python top20/tools/refresh.py top20/top20.json top20/top20.json

# 2) 판단 항목 검토·수정: alpha, act, cm, why, 실적 항목, meta의 결론 문구 → meta.judged를 오늘로

# 3) 기록 사본 저장
cp top20/top20.json top20/history/$(date +%Y-%m-%d).json

# 4) 커밋하면 사이트 TOP 20 탭에 바로 반영된다 (보기용 페이지 생성·발행 불필요)
```

## 커밋 규칙

- `top20/` 폴더 안의 파일만 추가·수정한다. 루트의 기존 파일은 건드리지 않는다.
- 여러 파일은 한 커밋으로 올린다.
- 자동 스캔(update.yml)이 도는 시간(평일 한국시간 09:30~15:30 매시 30분, 19:30)과 그 직후는 피한다. 스캔 작업은 푸시 전에 최신본을 받지 않으므로, 그사이에 다른 커밋이 끼면 스캔 결과 푸시가 거절될 수 있다.
- 이 저장소는 공개 저장소다. 여기 올린 판단과 보유 표시는 누구나 볼 수 있다.

## 채점

`history/` 파일의 각 종목 `Pup`(상승 확률)과 3개월 뒤 실제 수익률을 비교해, 확률 구간별(예: 55~60%, 60~65%) 실제 상승 비율을 확인한다.


## 오를 폭·내릴 폭 따로 (2026-10-23)
- 한 분포(정규분포)에서 같이 뽑으면 크기가 거의 같아, 기대 수익이 '(2 × 상승 확률 − 1) × 흔들림'이 되고 상승 확률 목록과 같은 종목을 고르게 된다(20개 중 15개 겹침).
- 오를 폭 = 위로 가장 가까운 매물대(최근 120거래일 거래대금이 가장 많은 구간의 40% 이상 몰린 가격대), 없으면 1년 고점
- 내릴 폭 = 아래로 가장 가까운 거래 밀집, 없으면 1년 저점, 국장은 PBR 1배 가격(주당 순자산)이 더 가까우면 그것
- 판단한 종목에만 쓴다 — 판단 없는 종목에 쓰면 51% 동전 던지기가 구조 폭만으로 기대 수익 목록을 채웠다(실측: 로켓랩 +27%, 버티브 +17%)
- 흔들림 기본값과 반씩 섞어 0.67~1.5배 안으로 — 가장 큰 매물대를 쓰면 많이 빠진 종목일수록 위 벽이 멀고 아래 바닥이 가까워 한쪽(역발상)으로 치우쳤다
- 판단 층: judgments.json의 종목에 up·dn(%)과 why_mag를 적으면 그 값을 쓴다(밸류·애널 목표가·신용 등 근거, 없으면 비워 둠)
